# M10: 並び、区画の順、行のアバター、見出しの統一（0.7）

Status: 未着手

最初に CLAUDE.md、docs/DESIGN.md、docs/DEVELOPMENT.md、docs/tasks/M9.md と、docs/design/ のすべてのボードを確認すること。挙動の正は DESIGN.md、見た目の正は docs/design/ である。M1〜M9 の指示書は完了した時点の記録で、DESIGN.md と食い違う箇所は DESIGN.md が優先する。0.7 で変更した文書は docs/DESIGN.md と docs/design/ のボードである。指示書と DESIGN.md が食い違う場合は、実装を止めてオーケストレーターに報告する。

## ゴール

0.6.0 の課題に 1 つの版で対応する。All の並びを行の時刻の順にし、Review と Mine の区画の順を変更し、行に出来事を起こした人のアバターと名前を表示する。マージキューへの追加の行を生成できなかった原因（PR の `updatedAt` が進まない）を、タイムラインの更新時刻で取得する方式で修正する。自分が起こした出来事の行を既読で生成する。見出しのボタンの並び、ウインドウの形、画面に表示するアプリの名前を shiibar-cc にそろえる。メニューを開いたあとにポップオーバーが閉じなくなる事象を修正する。

デーモン、CLI、ワイヤ形式、DB（版 9 への移行）、アプリを変更する。Keychain の項目は変更しない。

## 実装の要点

### 実装の前に確認すること

外部の動作に依存する点である。結果（方法と日付）を完了報告に記載する。DESIGN.md と異なる結果になった場合は、実装を止めてオーケストレーターに報告する。

- `timelineItems { updatedAt }` を `nodes(ids:)` の `Status` の要求に加えたときの引数（`first` または `last` が必要か）と、ポイントの消費（`rateLimit.cost`）。読み取りの要求で、公開リポジトリの実データを使用して確認する
- 行の actor のアバターを、`Events` の要求の出来事の `actor` と、コメントとレビューの `author` から `avatarUrl(size: 32)` で取得できること（型が `Actor` であることは公開スキーマで確認済み。DESIGN.md「API の使い分け」）。行を生成するすべての要求が対象である：`Events`、`TimelinePage`、`ThreadsPage`、`MergeQueue`、`Collect` とその続きの取得、`requestEvents`（`fetch.rs` の `COMMENT` と `ACTOR` の断片）。PR の本文のメンションの行は、PR の作者のアバターを使用する
- マージキューがマージした PR の `MergedEvent.actor` が誰になるか（キュー、またはキューに追加した人）。自分でキューに追加した PR の Merged の行が既読になるかが、これで決まる。判定は DESIGN.md のとおり出来事の `actor` で行い、結果を完了報告に記載する。公開リポジトリ（マージキューを使用しているもの）の読み取りの要求で確認する
- `NSWindow.CollectionBehavior` で、緑のボタンをフルスクリーンではなく拡大にする設定（macOS SDK のヘッダーで確認する）
- ポップオーバーの中のシート（グルーピング、Dismiss の確認）を表示している間にアプリが非アクティブになったときと、ポップオーバーを表示している間に同じアプリの常時表示ウインドウを押したときの、0.6 の動作と、修正のあとの動作。画面を表示する確認なので、最小のアプリで手順を用意し、操作は所有者に依頼する（オーケストレーターに報告する）。DESIGN.md の「未決」に記載している

### All の並び

- デーモンの `engine.rs`（CLI の `list --tab all` の順）と、アプリの `Listing.swift`（画面の順）の両方を変更する。同じ規則なので、基準の時刻の求め方を 1 か所ずつにまとめ、同じ入力で同じ順になることをテストで確かめる
- 基準の時刻は、カードの行のうち、今 List がオンの種類で、行の `muted` が偽の行の `occurred_at` の最大である。該当する行がなければ、カードの追加時刻である。アプリは、ワイヤのカードの `rows`（List がオフの種類の行を含まない）と行の `muted` から求める。カードの追加時刻はワイヤのカードの `added_at` である（値がないカードは 0.6 と同じ扱いにする）。Mute の対象のカードでも、Mentioned と My team mentioned の行は `muted` が偽なので数える
- 基準の時刻が同じカードの順は、0.6 の `Recently updated` で時刻が同じカードの順と同じ規則にする
- 並びの設定の保存の値（UserDefaults）は 0.6 のまま読み込み、`Recently updated` の記憶を `Recent activity` として扱う。保存の鍵と値の文字列を変更する場合は、0.6 の値を読み替える
- `Status` のグループの順番は、利用者が変更して記憶したアカウントでは記憶した順のままにする。記憶がないアカウントは新しい初期の順にする（0.6 は、グルーピングのシートで順番をドラッグしたときだけ順番を保存する）。`Status` のグループの初期の順は専用の並びにし、`PRStatus` の順（Filter の選択肢、要約、保存の形式）は変更しない

### 区画の順と未読の印

- 右クリックのメニューの `Move to …` の並び（1 枚と複数）は、DESIGN.md の表のとおり `Doing`、`Todo`、`Waiting`、`Done` のままにする。0.6 は表示の区画の順とメニューの並びに同じ定数（`PlacementSection.order`）を使用しているので、別の並びにする
- 区画の順は、画面（`Listing.swift` の区画の列）、CLI の `list` の出力、`--help` の説明で同じにする。ワイヤの `placement.section` の値、`place` の規則、区画の鍵（折りたたみと展開の記憶）は変更しない
- ↑↓ の移動、⇧↑／⇧↓ の範囲、ドロップの位置、`Done` へのドロップは、表示の順に従うので、区画の順を前提にした箇所（`Selection.swift`、`CardDrop.swift`、`SurfaceList.swift`）を確かめる
- 見出しの未読の印は、見出しの PR の数と同じカード（Filter が隠しているカードを除き、検索に依存しない）から求め、ShiibarGhCore の関数として実装してテストする。見出しの描画の画像の鍵に、印の種類（なし、点、輪）を含める（一覧の描画の規則。表示の条件が変化したときに再描画するため）
- All の折りたたんだ 1 段目のグループの印は、その中のすべての 2 段目のグループのカードから求める

### タイムラインの更新時刻

- `fetch.rs` の `Status` の要求に `timelineItems { updatedAt }` を加え、PR ごとに保存する（`store.rs`、版 9）。出来事を取得する条件は「PR の `updatedAt` が進んだ、またはタイムラインの更新時刻が保存した値より進んだ」である
- 保存した値がない PR は、値を保存するだけにする。0.6 からの更新の直後に、すべての PR の出来事を取り直さないためである
- 出来事の取得の範囲（`since`）は、0.6 と同じ規則（その owner で最後に取得に成功した時刻の 5 分前から）のままにする
- 偽の GitHub（`crates/shiibar-ghd/tests/fake_github/`）で、PR の `updatedAt` が進まずタイムラインの更新時刻だけが進む状況を作成し、Added to merge queue の行を生成することを確かめる

### 自分が起こした出来事の行

- `convert.rs` の、自分が再オープンした Reopened の行の扱いを、Merged、Closed、Added to merge queue、Removed from merge queue に広げる。判定は出来事の `actor` の login とアカウントの login の比較で、0.6 の Reopened の判定と同じ方法にする
- Removed from merge queue は、取り除いた人（出来事の `actor`）で判定する。キューに追加した人（本文の `added by`）では判定しない
- 既読で生成した行も、All の並びの基準に数える。配置、復帰の契機、自動の Dismiss の例外は、未読の行と同じである

### 行の 1 段目とアバター

- デーモン：行に actor のアバターの URL を保存し（`store.rs`、版 9）、ワイヤの行の `actor_avatar_url` で渡す（`shiibar-gh-proto`）。Merged、Closed、Reopened、Approved、Added to merge queue の行の `text` は 0.6 でも `null` で、`by <ログイン名>` はアプリが表示のときに作成している（`Presentation.swift` の `RowPresentation` と、`Listing.swift` の検索の一致の処理）。この 2 か所の `by <actor>` の生成を削除する。Review requested の行は、0.6 でも依頼した人を `actor` に保存している
- アプリ：`ListCells.swift` の行の描画を変更する。時刻と鎖のアイコンを右端に固定し、名前は残りの幅で省略する。アバターは、カードの見出しのアバターと同じ読み込みとキャッシュを使用する。画像を読み込めない間と URL がない行は、場所を空けずに名前だけを表示する
- 行の高さ：本文がなくなる行は 1 段になる。行の高さの計算、`Compact`、展開のアニメーション、一覧の描画の一致の確認（`SHIIBAR_GH_PERF_CONSISTENCY`）を確かめる
- ツールチップは、アバターと名前の両方に login を表示する（0.4 秒の待ち時間。「定数」）
- 検索の一致の表示（actor の名前の一致）が、新しい位置で動作することを確かめる

### 見出し、ウインドウ、名前

- 見出しのボタンの並び：`PopoverView.swift`。`app/Tests/ShiibarGhAppTests/TabRowTests.swift` は画像の濃い画素で位置を測定するので、見出しの並びの変更の影響を確かめる（CI の macos-15 でも確認が必要である。完了報告に記載する）
- 見出しの形：ポップオーバーの見出しを、帯（中央にアカウントの色の印とアカウント名。地は帯の見出しと同じ色、下に区切りの線）と、2 段目（左に `Updated …` と API の使用率、右にボタン）にする。長いアカウント名は `…` で省略する。色が None のアカウントは、名前だけを中央に配置する。最小の高さ（DESIGN.md「最小の高さ」）は見出しの高さから求めるので、文字の大きさ 9、12、18 の新しい値を完了報告に記載する（オーケストレーターが DESIGN.md に記載する）
- アカウントの色の印：丸を、角を丸めた四角（DESIGN.md「定数」）にする。ポップオーバーの見出し、ウインドウのタイトルバー、設定画面のアカウントの一覧（`PopoverView.swift`、`AccountsTab.swift` など）。設定画面の説明の文言は `the square next to its name` にする
- ウインドウ：`Surfaces.swift` の `NSPanel` と `.utilityWindow` を、macOS の標準のタイトルバーを持つ `NSWindow`（`[.titled, .closable, .miniaturizable, .resizable]`）にする。タイトルバーには、標準の 3 つのボタンと、中央のタイトル（アカウントの色の印とアカウント名）だけを表示する。ウインドウの `title` はアカウントの login にする。印の表示の方法（タイトルの文字に画像を付ける、タイトルバーの付属のビューを使用するなど）は、macOS SDK のヘッダーで API を確認して決め、完了報告に記載する。内容の領域には、見出しの 2 段目から下を表示する（アカウント名の帯は表示しない）。しまったウインドウは、メニューバーのアイコン、Dock、⌘Tab で元に戻して前面に表示する。緑のボタンはフルスクリーンにしない。Space をまたぐ動作（`collectionBehavior` のほかの値）は 0.6 のままにする。0.6 の動作を保つ：`Keep on top`、位置と大きさの記憶、最小の高さ、見出しのドラッグでの移動、フォーカスのないウインドウを前面に表示する押下からの移動、⌘W、通常のアプリへの切り替え
- ⌘R：ポップオーバーとウインドウで、検索欄にいる間と Dismissed の一覧でも Refresh を実行する。取得中、シートを表示している間、設定画面では何もしない。メニューの項目は追加しない
- 名前：`grep -rn 'shiibar-gh' app/Sources` で画面に表示する文字列を確かめ、DESIGN.md の文言に合わせる（`MainMenu.swift`、`PopoverView.swift`、`SettingsView.swift`、`Presentation.swift`、`BoardIcons.swift`、`Surfaces.swift` のツールチップ）。`NSLog` の出力、ファイルの種類の識別子、Create token の URL は変更しない
- メニューバーのアイコン：左のボタンと右のボタンのどちらを離したときも、同じ動作にする
- `Grouping…`（`FilterViews.swift`）と `Restore`（`ListCells.swift`）：大きさは DESIGN.md「定数」とボードに従い、文字の大きさの比率で連動させる。`Grouping…` は 0.6 では標準の `NSButton` で高さが固定なので、アプリが描画するボタンにする（動作、アクセシビリティの役割と名前、キーのフォーカスを受け取らないことは 0.6 と同じ）

### ポップオーバーを閉じる

- `Surfaces.swift` で `NSApplication.didResignActiveNotification` を受け取り、ポップオーバーを表示していれば閉じる。計測のモード（`.applicationDefined`）のポップオーバーは対象外にする
- 閉じたときの処理（`popover_closed` の送信、スクロールの位置の破棄など）は、0.6 でポップオーバーが閉じたときと同じ処理を使用する
- 常時表示ウインドウは対象外である

### DB と移行

- スキーマは版 9。`SCHEMA_VERSION` を 9 にする。版 8 から版 9 への移行は、PR のタイムラインの更新時刻の列（値なし）と、行の actor のアバターの URL の列（値なし）の追加である。既存の行の本文と未読は変更しない
- `store.rs` の `open_verified` は、版 6 → 版 7 → 版 8 → 版 9 の順に移行を実行する。`user_version` は最後の移行のあとで書き込む（0.6 の `migrate_v7_to_v8` は自分で書き込んでいる）。`migrate_accounts_only`（版 5 と版 4）は `user_version` に 9 を書き込む。どれも 1 つのトランザクションで行い、失敗したら元の版のまま「DB を読めないとき」にする
- 移行のテストのスキーマ `crates/shiibar-ghd/tests/data/schema_v06.sql` は、タグ `v0.6.0` の `store.rs` から作成する。行のデータは、ほかの版と同じく `tests/migration.rs` に記述する

## 危険な箇所と確認すること

- **DB の移行**：版 8 のすべてのデータ（行の本文と未読を含む）を保つこと。途中の失敗でロールバックし、版 8 のまま「DB を読めないとき」になること

- **操作の速さ**：M7 の基準（DESIGN.md「実装方針」の「操作の速さ」）を保つ。行のアバターの描画を加えるので、スクロールの計測を画面に表示しないモード（`SHIIBAR_GH_PERF_HIDDEN=1`）で行う

## ルール

- ソースコード、コメント、テスト名、文字列は英語で記述する。UI の文言はボードと DESIGN.md の英語の表記に従う
- 仕様を日本語のまま引用しない。英語に訳して DESIGN.md の節名を示す
- コードのコメントとテストの名前は、その処理が必要な条件と理由を記述し、発見の経緯を記述しない
- テストデータとサンプルには、架空の名前とパスを使用する
- 指示書の範囲外の機能を追加しない。DESIGN.md に記載のない動作が必要になったら、実装を止めてオーケストレーターに報告する

- エージェントが cargo を実行するときは、所有者が使用している `target/` と競合しないよう、別の `CARGO_TARGET_DIR` を指定する
- `scripts/dev-install.sh` と `scripts/dev-uninstall.sh` はエージェントが実行しない
- 画面に表示される計測を繰り返さない。確認は画面に表示しないモードで行う
- コミットはオーケストレーターの指示があるまで行わない
- 完了報告には、実装者が決めた点と、仕様の矛盾や不足を記載する。ビルドの警告の件数も記載する
