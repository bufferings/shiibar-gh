# M5: 0.2.0 の感想への対応（0.3）

Status: 着手前

最初に CLAUDE.md、docs/DESIGN.md、docs/DEVELOPMENT.md、docs/tasks/M1.md〜M4.md と、docs/design/ のすべてのボードを確認すること。挙動の正は DESIGN.md、見た目の正は docs/design/ である。M1〜M4 のブリーフは完了した時点の記録で、DESIGN.md と食い違う箇所は DESIGN.md が優先する。指示書と DESIGN.md が食い違う場合は、実装を止めてオーケストレーターに報告する。

## ゴール

所有者が 0.2.0 を 1 日使用して挙げた 20 件の感想に、1 つの版で応える。中心は Todo と Done の廃止で、行はすべて「起きたことの記録」になり、「自分のレビュー待ち」は PR の状態としてカードとメニューバーの数字に表示する。ポップオーバーは、絞り込みのチップの行と、検索欄・Group by・並びの行の 2 行構成になる（docs/design/Main.html）。行は操作で既読にし、クリックは選択、ダブルクリックは開く、右クリックはメニューになる。取得の失敗は短い間隔で再試行し、通知 API は既知の PR の再取得の合図にだけ使用する。

### DB と移行

- スキーマは版 5。0.2（版 4）の DB は起動時に移行し、アカウント、owner、出来事の表（Todo の列は捨てる）、Exclusions、PR、行、未読、Snooze、監視開始時刻、取得の記録を引き継ぐ。Todo と Done の値は捨てる。移行は 1 つのトランザクションで行い、失敗したら「DB を読めないとき」の状態にする。0.1（版 3 以前）の DB は M4 のまま「DB を読めないとき」の状態にする。版がプログラムより新しい DB は M1 のままエラーで終了する
- Keychain の項目（service `shiibar-gh`、account `accounts`、版 2）は変更しない
- 行の `seen_pending`、`todo_auto`、手の `todo`、`done` の列は削除する。カードの `created_at` を追加する。レビュー待ちの状態は PR の最新の値（レビューの依頼と自分のレビューの有無）から求め、列に保存するかは実装者が決める

### 取得

- 再試行：アカウントの取得が終わるたびに次までの待ち時間を決める。成功なら通常の間隔。失敗なら 5、10、20、40 秒と延ばし、通常の間隔を超えたら通常の間隔。タイマーは 1 本で、次の取得は前回の終わりから数える。`refresh` はいつでもすぐ実行し、再試行の回数を変更しない。`fetch_failed` の警告は、最初の失敗から 5 分たっても成功していないときに付け、成功で除く。`until` は次の再試行の時刻
- 本文が空、または JSON として解釈できない 200 の応答は、ネットワークの失敗と同じ扱い（再試行の対象）にする
- `updated_at` はそのアカウントの取得が最後に成功して終わった時刻。失敗が続く間は進まない。成功がなければ `null`（アプリは `Not updated yet`）
- 通知 API：通知された PR のうち、repo#number → id の対応をすでに持つ PR だけを再取得の対象にする。対応のない PR は無視し、id を引かない。If-Modified-Since と X-Poll-Interval の扱いは M4 のまま
- SSO：`X-GitHub-SSO` の `organizations=` の id が登録済みの owner の `github_id` に一致したときだけ `sso_required` を付ける。一致しなければ何もしない
- `createdAt` を PR の取得に追加する

### 行と既読

- 行の生成時に決めるのは `notify`（表の Notify、Exclusions、Skip draft pull requests から）だけである。List は表示時に今の表と Exclusions から求める（M4 のまま）
- 既読：`read`（行 id の配列）は指定した行の未読を下ろす。`read_all`（アカウント）はそのアカウントのすべての行の未読を下ろす。`seen` は削除する。`popover_opened`／`popover_closed` は残し、メニューバーの青い点と行の整理、カードの消滅の反映の時点にだけ使用する（行の既読は変更しない）。既読になった行の整理（PR ごとに新しい 3 件）とカードの消滅は、ポップオーバーを閉じたときに反映する
- レビュー待ちの判定は M4 の「今もやることか」の判定（GitHub の今の reviewRequests）を流用し、チーム宛ては「その owner の Review requested to my team の List がオン」のときだけ数える。Snooze 中、読めなくなった PR、Hidden のリポジトリの PR、依頼した利用者が Hidden または List only の依頼は数えない。レビュー待ちの PR はカードを残す（「カードが出る・消える条件と監視期間」）
- 監視開始より前の出来事の例外（今も続くレビュー依頼は未読の行にする）は M4 のまま

### 表示（アプリ）

- ボード Main.html と Activity.html に従う。チップの行はチップごとの固有の幅で左寄せにし、ポップオーバーやウインドウの幅に合わせて伸ばさない
- Group by、並び、絞り込みの選択、折りたたみ、Activity の owner の選択、ウインドウの位置と Keep on top はアカウントごとに UserDefaults に保存する。検索の文字と `+ N more PRs` の展開は保存しない
- 並びと Group by の計算、`+ N more PRs` の畳み方、検索の一致、Status と Involvement の分類は UI から分離して `swift test` で確認する
- 文字の大きさ：`text_size` を本文の大きさとし、ほかの文字、行の高さ、アバター、ポップオーバーとウインドウの幅を 12 に対する比率で連動させる。`config_changed` で即時に反映する。⌘=（⌘+ も）、⌘−、⌘0 は `config_set` を送る
- Keep on top は NSPanel の `level` を切り替える。値は UserDefaults に保存し、次に開いたときに復元する
- クリックの選択、ダブルクリックの開く、右クリックのメニューはカードの見出しと行で同じ作りにする。チェックボックスは削除する
- 見出しの `API 25%` は GraphQL と REST の使用率の高い方。`rate_limit` が `null` なら `API –`。80% 以上は警告の色。マウスを乗せると両方の数
- Add account… と Edit… のシートは、開いた時点でテスト結果の領域を確保し、結果が出るまで項目名を薄く表示する（Sheets.html）

### ワイヤ形式と CLI

- DESIGN.md の「ワイヤ形式」に従う。アカウントと owner の `todo_count` は `review_count` に、行の `todo`／`done` は削除、カードに `created_at`、`updated_at`、`awaiting_review`（レビュー待ち。絞り込みの `review_requested` とは別）を持たせる。`todo`、`done`、`seen` の要求は削除し、`read`、`read_all` を追加する
- CLI：`version`（CLI の版とデーモンの `info` の版。`--json`。デーモンに接続できなくても終了コード 0）、`list` の `--todo` の削除、`done`／`todo` の削除、`read <row>…` と `read --all --account <a>`、`list --search <text>`、`config get|set text_size`。`--help` を更新する
- `dev_ingest` は Todo の指定を削除し、PR の `createdAt` を渡せるようにする

## 確認した外部仕様

実装前に次を確認し、確認方法を完了報告に記載する。確認できないものは DESIGN.md の「未決」に残す。

- SwiftUI で文字の大きさを比率で連動させる方法（`dynamicTypeSize` ではなく固定の pt を使用しているため、実装者が方法を決めて記載する）
- SQLite のスキーマ変更（列の削除）を 1 つのトランザクションで行う方法（`ALTER TABLE DROP COLUMN` の対応版。rusqlite が同梱する SQLite の版で確認する）

## テストの方法

- M2.md と M4.md の「テストの方法」のとおり、既定のビルドのテストは実際の Keychain とネットワークに触れない
- 版 4 の DB からの移行は、タグ `v0.2.0` の `store.rs` のスキーマから作成した固定の SQL を `tests/data` に保存し、移行後にアカウント、owner、行、未読、Snooze が残り、Todo と Done の列がないことを確かめる
- 新しく確かめること：レビュー待ちの判定と `review_count`（自分宛て、チーム宛て、List オフのチーム、Snooze 中、レビューを投稿したあと、依頼の取り消し）、`read`／`read_all` と整理、`popover_closed` を送っても既読にならないこと、再試行の間隔と 5 分の帯（偽の時計）、`updated_at` が失敗で進まないこと、本文が空の応答の扱い、通知 API で未知の PR を取り込まないこと、SSO の警告が登録済みの owner だけに付くこと、`text_size` の範囲、`version` の出力、`list --search`
- 削除した機能（Todo、Done、T／D、`--todo`、使用量の帯、Activity の owner 列、`seen`）のテストは削除する
- アプリのロジック（Group by の分類、並び、開いている PR を先に、`+ N more PRs`、検索の一致、チップの選択、キーのヒント、右クリックのメニューの項目、`API 25%` の値、文字の大きさの比率、Keep on top の保存）は UI から分離して `swift test` で確認する
- テストは実際の状態ディレクトリ、ホーム、Keychain、ネットワーク、通知センター、ログイン項目、標準の UserDefaults に触れない
