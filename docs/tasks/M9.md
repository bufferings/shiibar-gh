# M9: Mine の区画と Done の Dismiss all（0.6）

Status: 段階 6（所有者の確認）まで完了。0.6.0 として公開する

最初に CLAUDE.md、docs/DESIGN.md、docs/DEVELOPMENT.md、docs/tasks/M8.md と、docs/design/ のすべてのボードを確認すること。挙動の正は DESIGN.md、見た目の正は docs/design/ である。M1〜M8 の指示書は完了した時点の記録で、DESIGN.md と食い違う箇所は DESIGN.md が優先する。0.6 で変更した文書は docs/DESIGN.md と docs/design/ のすべてのボード（Main.html と Settings.html は内容と色、ほかのボードは色の記述だけ）である。指示書と DESIGN.md が食い違う場合は、実装を止めてオーケストレーターに報告する。

## ゴール

0.5.0 の課題に 1 つの版で対応する。中心は Mine の区画である。0.5 の Mine は順位を付けた 1 本の一覧と `Done` だけで、作業中、レビュー待ち、まだ取りかかっていない自分の PR を区別できない。0.6 は Mine を Review と同じ `Doing`、`Todo`、`Waiting`、`Done` の 4 つの区画にし、規則も Review にそろえる。あわせて、`Done` の見出しの `Dismiss all`、Dismissed の一覧のリポジトリごとのグループ、色が None のアカウントの丸の削除、大きい文字の大きさでのタブの行の表示のモードの切り替えと Dismissed のボタンのそろえ方、画面の色の macOS のシステムカラーとアクセントカラーへの移行に対応する。マージキューの行が表示されなかった事象は、原因を調べてから扱いを決める。

デーモン、CLI、ワイヤ形式、DB（版 8 への移行）、アプリを変更する。Keychain の項目は変更しない。

- `Dismiss all` は見出しの PR の数の右、山形の左に表示する。見出しの要素の並びは、名前、`Show less`（展開中だけ）、数、`Dismiss all`、山形である（DESIGN.md「区画の表示数」）

- Dismiss するのは押した時点の対象のカードで、シートを表示している間に一覧が更新されても数と対象を変更しない。確定した時点でその `Done` にない対象のカード（ほかの操作で Dismiss した、別の区画またはタブに移動した、再オープンで元の区画に戻った、カードが削除された）は処理しない

- Dismissed の一覧の見出しの数とグループの順は、検索に依存しない。見出しは選択の対象ではなく、クリックと右クリックのどちらでも何もせず、選択を変更しない

## 実装の要点

### マージキューの行の調査

作業の順序の 1 で、ほかの変更より先に行う。推定で修正しない。

- 事象：アカウント自身がマージキューに追加した PR で、`Added to merge queue` の行がカードに表示されなかった。DESIGN.md「行の種類の判定」は ADDED_TO_MERGE_QUEUE_EVENT から操作した人に関係なく行を生成し、`convert.rs` にも自分の操作を除く条件はない
- 確かめる候補（どれも DESIGN.md のとおりの動作でありうる）：
  - その owner の出来事の表で、Added to merge queue の List がオフになっている（「表の適用」。List がオフの間の行は表示しない）
  - マージキューへの追加とマージ（またはキューからの取り除き）が 1 回の取得の間隔の中で起き、カードの行の表示が新しい 3 件だけなので、`+ N more` の中にある（「カードの中の行」）
  - PR を初めて検出した時点ですでに閉じていて、新しく発見した閉じた PR として復帰の契機の行だけを生成した（「Dismiss」の「復帰の契機」、「API の使い分け」）
  - マージキューへの追加で PR の `updatedAt` が進まず、出来事を取得しなかった（「API の使い分け」：`updatedAt` が進んだ PR の出来事を取得する）。GitHub がキューへの追加で `updatedAt` を更新するかは確認していない
  - `timelineItems(since:)` の `since` が、キューへの追加の出来事を除いた（`since` が出来事の時刻と比較されるかは確認していない）
  - 出来事の取得の範囲（owner の最後の成功の 5 分前から。「監視開始より前の出来事」）の外だった
- 方法：まず CLI の `activity --json`（`kind` が `merge_queue_added` の行の有無）、`owner events`、デーモンのログで状態を確かめる。実データの確認は GitHub の読み取りだけで行う（`gh api graphql` で、その PR の `updatedAt` とタイムラインの `ADDED_TO_MERGE_QUEUE_EVENT`、`since` を指定した場合と指定しない場合）。確認した日付と方法を完了報告に記載する
- 再現できたら、偽の GitHub（`tests/fake_github`）か `dev-ingest` のテストで同じ状況を作成し、原因を固定する
- 原因が DESIGN.md と異なる動作なら修正し、テストを加える。DESIGN.md のとおりの動作、または GitHub の API の仕様によるもの（`updatedAt` や `since` の扱い）なら、修正せずにオーケストレーターに報告する（DESIGN.md の変更は所有者が判断する）。原因が特定できないときも、確かめた候補と結果を報告する

### DB と移行

- スキーマは版 8。`SCHEMA_VERSION` を 8 にする。版 7 から版 8 への移行はデータだけの変更で、表の形は変更しない。tab が `mine` で `place_section` が `'main'` の値を `'todo'` にする 1 つの UPDATE で、開いているカード、Dismiss しているカード、Mute の対象のカード、`Done` のカードの `Done` に入る前の区画のすべてを移す（列の名前は `store.rs` で確かめる）。順位の値は変更しない。Mine の `Done` のカード、`Done` に入った時刻と連番、Review の配置は変更しない

### 要求の順

- 1 つのアカウントの手元で完結する操作の要求（配置と順位、Dismiss、Restore、Mute と解除、既読）は、操作の順にデーモンへ届けること（DESIGN.md「操作の反映」）。要求ごとに接続するので、続けて送ると後の要求が先に届くことがあり、デーモンの状態が画面の表示と異なる状態で終わる（D のあとに T を押したカードが、次の再取得で Doing に戻る）。前の要求の応答を受け取ってから次の要求を送る。画面への反映は待たず、失敗したときに元に戻すのはその操作の変更だけで、後の要求は送る

### `Dismiss all`

- 対象のカードは、M8 の Filter と検索を適用したあとの表示するカード（`+ N more PRs` にまとめたカードを含む）を求める既存の判定で求める。見出しの数は検索を適用しないので、対象とは一致しない場合がある。別の判定を作成しない。`Unread only` で表示を続けているカードは表示しているカードである
- 要求の送り方と失敗の扱いは、複数のカードの Dismiss（⌫）と同じ処理を使用する
- 確認のシートは × の確認のシートと同じ実装を使用し、題と説明だけを変更する。`Don't ask again` は同じ設定を変更する
- 見出しの描画の画像の鍵に、`Dismiss all` の有無を含める（M7 の一覧の描画の規則。表示の条件が変化したときに見出しを再描画するため）

### Dismissed の一覧

- グループの見出しは、All の 1 段目のグループの帯と同じ見た目で、山形を持たない。選択の対象にせず、右クリックでも何もしない。同じ時刻のグループは owner/repo を大文字と小文字を区別せずに比べた昇順に並べる

## 危険な箇所と確認すること

- **DB の移行**：`main` のカードの相対の順が `Todo` でそのまま保たれること（ワイヤの `placement.position` で確かめる）。Dismiss しているカードの元の場所（復帰の先）が `Todo` になること。`Done` のカードの `Done` に入る前の区画が `todo` になり、再オープンで `Todo` の元の順位に戻ること。途中の失敗でロールバックし、版 7 のまま「DB を読めないとき」になること。版がプログラムより新しい DB でデーモンがエラーで終了する動作を変更しないこと
- **Mine のキー**：0.5 で何もしなかった D／T／W が Mine で動作し、All では引き続き何もしないこと。検索欄にいる間の D、T、W は文字の入力のままであること
- **単一の一覧を前提にしたテスト**：Mine を 1 本の一覧と `Done` として扱うテスト（デーモンの表形式のテスト、CLI のテスト、`swift test` のメニュー、キーのヒント、ドロップの位置、空の区画、`+ N more PRs` の鍵）は、削除せず Review と同じ前提に書き換える。書き換えたテストの一覧を完了報告に記載する
- **`Dismiss all` の対象**：Filter と検索で隠したカードを含めないこと、`+ N more PRs` にまとめたカードを含めること、検索中は対象の数が見出しの数より少ない場合があること、折りたたみ中と対象が 0 枚または 1 枚のときにボタンを表示しないこと（検索や Filter で対象が 1 枚に減ったときを含む）、シートを表示している間の一覧の更新で対象を変更しないこと、確定した時点でその `Done` にないカードを処理しないこと、選択している項目がなくなったときに選択なしになること
- **操作の速さ**：M7 の基準（DESIGN.md「実装方針」の「操作の速さ」）を保つ。計測は画面に表示しないモード（`SHIIBAR_GH_PERF_HIDDEN=1`）で、変更と関係する場面（Mine の区画の間の移動、`Dismiss all`、Dismissed の一覧の表示と検索）だけを行う
- **一覧の描画の一致**：`SHIIBAR_GH_PERF_CONSISTENCY` の確認に、Mine の 4 つの区画、`Dismiss all` の表示の切り替え、Dismissed の一覧のグループの場面を加える
- **テストの隔離**：テストは実際の Keychain、ネットワーク、状態ディレクトリ、ホーム、通知センター、ログイン項目、標準の UserDefaults に触れない
