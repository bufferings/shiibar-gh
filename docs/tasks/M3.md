# M3: Swift アプリ、署名、リリース

Status: 指示書レビュー

最初に CLAUDE.md、docs/DESIGN.md、docs/DEVELOPMENT.md、docs/tasks/M1.md、docs/tasks/M2.md と、docs/design/ のすべてのボードを確認すること。挙動の正は DESIGN.md、見た目の正は docs/design/ である。指示書と DESIGN.md が食い違う場合は、実装を止めてオーケストレーターに報告する。

## ゴール

利用者がアプリをインストールすると、メニューバー、ポップオーバー、常時表示のウインドウ、設定画面、macOS の通知が、DESIGN.md とボードのとおりに動作する。アプリはデーモンを起動、停止、更新し、CLI と同じソケットでデーモンと通信する。リリース版を Developer ID で署名して公証し、GitHub Releases と Homebrew の cask で配布する仕組みをそろえる。

## 範囲

### 含める

- `app/` の Swift package（SwiftUI。足りない部分は AppKit）。アプリのバンドルの組み立て
- デーモンのライフサイクル（「デーモンのライフサイクル」）
- ソケットのクライアント。`subscribe`（`client` は `app`）、再接続、要求と応答
- メニューバー：スコープごとのアイコン、バッジ、青い点、三角（docs/design/MenuBarIcon.html）
- ポップオーバー：見出し、帯、タブ、チップ、カード、行、キーのヒント、空の状態、DB を読めないときの表示（docs/design/Main.html、MainSnoozed.html、PublicScope.html）
- 常時表示のウインドウ（Open in window。NSPanel）
- 未読の消え方のための `seen`、`popover_opened`、`popover_closed` の送信
- キーボードの操作（DESIGN.md の「キーボード」と「選択とキー」）
- macOS の通知：個別の通知、まとめ通知、Done と Snooze のボタン、押したときの動作、不在の間の保持
- 設定画面：General、Scopes、Notifications、Watching の 4 タブ（docs/design/Settings.html）。スコープの追加とトークンの登録、Create token、テストの結果、API の使用量、SSO の警告
- Launch at login（SMAppService）
- 開発版のインストール：`scripts/dev-install.sh`、`scripts/dev-uninstall.sh`、ローカルの固定の署名の ID の作成
- リリース：GitHub Actions のリリースのワークフロー（Developer ID の署名、hardened runtime、公証、staple、zip、GitHub Releases）、Homebrew の cask のテンプレートと、tap を更新するワークフロー
- CI に Swift のテストのジョブを追加する

### 含めない

- デーモンの挙動の変更。ワイヤ形式に足りない情報が見つかった場合は、実装を止めてオーケストレーターに報告する（DESIGN.md の変更になるので所有者が決める）
- 実際のリリースの公開、tap への push、GitHub の Secrets の登録。所有者が行う
- GitHub への書き込み

## 確定事項

### 決定済みの方針

所有者が 2026-11-05 に決めた事項で、DESIGN.md に反映済みである。

- 配布と署名は DESIGN.md の「配布と署名」に従う。参考になる実装は `../shiibar-cc` の `.github/workflows/release.yml`、`.github/workflows/bump-cask.yml`、`packaging/homebrew/shiibar-cc.rb`、`scripts/dev-install.sh`、`scripts/dev-uninstall.sh`、`scripts/lib/` にある。コピーではなく、shiibar-gh の名前と構成に合わせて採用する
- 設定画面の Cost per poll は今の値だけを表示する。「Before your changes」は表示しない（ボードから削除済み）
- 設定画面は Repository access を表示しない（ボードから削除済み）。トークンの入力の案内で、選ぶべき Repository access を示す（DESIGN.md の「設定画面でのスコープの追加とトークンの登録」）
- 登録済みのトークンは 12 文字の固定の `••••••••••••` で表示する
- 警告の三角と帯の文面は DESIGN.md の「警告の表示」に従う
- 不在の判定と通知の保持は DESIGN.md の「macOS 通知」に従う

### デーモンのライフサイクル

- `.app` の `Contents/Helpers/` に `shiibar-ghd` と `shiibar-gh` を同梱する
- アプリの起動時に `info` で既存のデーモンを確認する。応答があり、`version` が同梱のデーモンと同じなら接続する。異なれば `shutdown` で止めてから同梱のデーモンを起動する。応答がなければ同梱のデーモンを起動する
- アプリを終了するときは `shutdown` でデーモンを止める。DESIGN.md の「監視開始より前の出来事」の「アプリの停止中に起きた出来事」は、デーモンがアプリと一緒に止まる前提である
- デーモンが予期せず終了した場合の扱い（再起動の有無と間隔）は、実装者が決めて完了報告に記載する。launchd は使用しない（DESIGN.md の「構成」）
- デーモンの stderr のログの扱いは実装者が決め、完了報告に記載する
- 再接続は 1 秒から倍々、上限 30 秒である（DESIGN.md の「定数」）。再接続したら、開いているスコープの `popover_opened` を再送する（DESIGN.md の「ワイヤ形式」）
- 状態ディレクトリは `SHIIBAR_GH_STATE_DIR` に従う（DESIGN.md の「定数」）。アプリはこの環境変数を起動したデーモンに引き継ぐ。テストはこれで隔離する

### ソケットのクライアント

M1 の「shiibar-cc の実装から引き継ぐ注意点」のうちクライアントの項目に従う。1 行が複数回の読み取りに分かれても処理する。未知の `event`、フィールド、enum の値を無視する。

### メニューバーとポップオーバー

- MenuBarExtra で試し、スコープごとのアイコン、バッジ、キーボードの操作が足りなければ AppKit（NSStatusItem と NSPopover）にする（DESIGN.md の「UI」）。どちらにしたかと理由を完了報告に記載する
- アイコンはスコープごとに 1 つ、幅は固定。disabled のスコープのアイコンは表示しない。アイコンの形は owner の種類（org、user、Public）で決まる
- チップの選択、常時表示のウインドウの位置と大きさは UserDefaults に保存する（DESIGN.md の「状態の保存」）
- 行が画面に表示されたら `seen` を送る。スクロールの外の行と、絞り込みで隠れた行は送らない
- ポップオーバーを閉じたとき、常時表示のウインドウが手前から外れたときに `popover_closed` を送る
- 行と見出しと状況アイコンを押すと、`open` で求めた URL をブラウザで開く

### 通知

- UNUserNotificationCenter を使用する。`notify` の `notification` の `title`、`subtitle`、`body` をそのまま表示する
- 個別の通知を押すと `url` をブラウザで開く。ポップオーバーは経由せず、青い点の状態は変更しない。Done と Snooze のボタンを付ける（DESIGN.md の「macOS 通知」）
- まとめ通知を押すと、そのスコープのポップオーバーを開く
- 不在の間に受け取った通知は表示せずに保持し、戻ったときにスコープごとにまとめる。まとめの規則と文面は DESIGN.md の「macOS 通知」に従う

### 設定画面

- 値の読み書きは `config_get` と `config_set`、表示する値は `settings_status`、スコープは `scope_*`、トークンは `token_set` と `token_test` で行う
- 不正な値はデーモンが `invalid` で拒否する。アプリはその値を保存せず、エラーを表示する
- アプリはトークンを保持しない。Save で `token_set` に渡したら破棄する。ログ、UserDefaults、クラッシュの記録に含めない

### Keychain

アプリは Keychain に触れない。トークンの保存と読み取りはデーモンだけが行う（CLAUDE.md）。

## 実装前に決める事項

段階 1 のレビューで、次の事項の案を作成する。所有者の判断が必要なものは、オーケストレーターがまとめて確認する。

- アプリの名前（`.app` の名前）、bundle identifier、アプリのアイコン（ボードがない）、対応する macOS の最低の版
- 版の番号の付け方と、タグとの対応。デーモンの `info` の `version` との関係
- 不在の間の通知をまとめるときに必要な情報（行の数と PR の数）が、今のワイヤ形式の `notification`（`rows`、`pr`）で足りるか。まとめ通知の `pr` は `null` なので、PR の数を求められない場合がある
- 常時表示のウインドウを開いている間の `popover_opened` と `popover_closed` の送り方（ポップオーバーと同時に開いている場合を含む）
- スコープの追加とトークンの入力の画面はボードにない。既存のボードのコンポーネントで構成する案を作成する
- その他、DESIGN.md とボードだけでは決まらない画面の動作

## テストの方法

- アプリのロジック（スナップショットからの表示の状態、絞り込み、選択とキー、`seen` を送る行の決定、警告の帯と三角、不在のまとめ、デーモンのライフサイクルの判定）は、UI から分離して `swift test` で確認する
- ソケットのクライアントのテストは、テスト用の一時ディレクトリで待ち受ける偽のデーモン、または `SHIIBAR_GH_STATE_DIR` を一時ディレクトリにした実際のデーモン（`dev-ingest` ビルド）を使用する
- 通知、Launch at login、ブラウザで開く処理は差し替えられる形にし、テストでは偽の実装を使用する
- テストは実際の状態ディレクトリ、ホーム、Keychain、ネットワーク、通知センター、ログイン項目に触れない
- `scripts/dev-install.sh` と `scripts/dev-uninstall.sh` は、`~/Applications`、ログイン項目、Keychain（署名の ID）を変更するので、エージェントは実行しない。shellcheck などの静的な確認だけを行い、実行は所有者の確認（段階 6）で行う
- リリースのワークフローは Secrets がないと実行できない。YAML の構文の確認と、cask のテンプレートの `brew style --cask` だけを行う

## 完了条件

ローカルで次のコマンドが成功すること。CI は push 後に実行されるので、完了条件に含めない。

```sh
cargo test --workspace --all-features --locked
cargo test --workspace --locked
cargo clippy --all-targets --all-features --locked -- -D warnings
cargo deny check
swift test --package-path app
```

- 仕様との比較と独立検証で未解決の指摘がない
- 所有者が `scripts/dev-install.sh` でインストールし、実機で確認する（DEVELOPMENT.md の段階 6）。あわせて、再ビルドとインストールで Keychain の許可のダイアログが出ないことを確かめる
- 所有者が Secrets を登録してリリースのワークフローを実行し、cask でインストールできることを確かめる

## ルール

- ソースコード、コメント、テスト名、文字列は英語で記述する。UI の文言はボードと DESIGN.md の英語の表記に従う
- 仕様を日本語のまま引用しない。英語に訳して DESIGN.md の節名を示す
- 指示書の範囲外の機能を追加しない
- 外部仕様（Apple の API、codesign、notarytool、Homebrew の cask の DSL、GitHub Actions）を記憶だけで実装しない。公式ドキュメントまたは実物で確認し、完了報告に確認方法を記載する
- GitHub Actions の `uses:` はフルコミット SHA で固定する
- 依存のパッケージ（Swift Package と crate）は、公開から 7 日以上たった版だけを使用する（DEVELOPMENT.md の「依存クレートのクールダウン」）。追加する場合はオーケストレーターに報告する
- エージェントが cargo を実行するときは、所有者が使用している `target/` と競合しないよう、別の `CARGO_TARGET_DIR` を指定する
- 完了報告には、実装者が決めた点と、仕様の矛盾や不足を記載する
