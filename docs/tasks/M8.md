## ゴール

一覧を絞る操作を、操作の行の `Filter` にまとめる。発端は、M7 のデモの確認での所有者の感想である（「これだけ多いと、Show Mutedしたときにどこにあるか分からないね」「フィルタの見せ方含めて改善したいですね。」）。M7 では、絞る手段が検索欄と `Show muted`（全部表示するか、全部隠すか）だけで、Mute の対象のカードだけを表示する方法がなく、絞っていることも一覧から分かりにくかった。

M8 は、`Filter` を開閉する領域にする。閉じている間は、既定から変更した指定を 1 行で表示する。開くと、タブごとに Mute（`Hide`、`Show`、`Only`）、PR の状態、`Unread only` を指定でき、All ではグルーピングと並びも同じ場所で指定する。M7 の `Show muted` の切り替えは Filter の Mute の指定に置き換え、`Compact` の切り替えはアイコンだけで表示する。

変更はアプリ（Swift）だけである。デーモン、CLI、ワイヤ形式、DB、Keychain の項目は M7 から変更しない。

## 実装の要点

### 絞る指定と一覧

- 今の `showMuted`（`Listing`、`SurfaceList`、`AppModel`、`Services` の UserDefaults の `showMuted.` の鍵）を、タブごとの Filter の値に置き換える。値は、Mute（3 つ）、状態（4 つの真偽）、`Unread only`（真偽）である。`Listing` の「表示するカード」を求める箇所（表示、見出しの数、`+ N more PRs`、空のグループと区画、⇧R の対象、選択の解除、ドロップの位置の基準）は、すべて同じ 1 つの判定を使用する
- 状態の分類は、Group by の `Status` と同じ関数を使用する
- `Unread only` の判定は、タブの未読の数と同じ「青い未読の行を持つカード」である。別の判定を作成しない
- 絞る指定は ShiibarGhCore の値と関数として実装し、画面から分離してテストする
- M7 の `Listing.emptyText` と `rowsToRead` は `showMuted: Bool = true` の既定の引数を持つ。Filter の値には既定の引数を付けず、呼び出す側が必ず渡すようにする（判定を省略する呼び出しを残さないため）

### `Unread only` で既読になったカード

- 「表示を続けているカード」の状態を、ポップオーバーとウインドウのそれぞれが持つ。時刻は注入できるようにし、テストで 5 秒を待たない
- 5 秒の起点は、青い未読の行を持たなくなった時点と選択が離れた時点の遅いほうである。再び選択すると最初から数える
- 行の中の項目（行、カードの中の `+ N more` など）を選択している間も、そのカードを選択しているものとして扱う
- 表示を続けるカードの集合は、選択の解除（表示されなくなったカードの選択を解除する規則）より先に求める。逆の順にすると、選択中のカードが既読になった時点で選択が解除され、同時に隠れる
- 「青い未読の行を持たなくなった」ことの検知には、画面ごとに前回のカードの状態が必要である。もう一方の画面や CLI での既読（`account_changed` のあとの再取得）と、Mute と Unmute による青と灰色の変化でも検知する
- ドラッグ中と右クリックのメニューを表示している間は隠さない。隠すときのスクロールの位置の規則は DESIGN.md「Filter」に従う
- 薄くする表示（最後の 0.3 秒）と、隠したあとの一覧の更新で、M7 の一覧の描画の規則（行の画像の鍵の比較、表示中の行のビューの位置と表の並びの一致）を保つ。薄くした状態を行の画像の鍵に含めるか、画像とは別に不透明度で表現するかは実装者が決め、完了報告に記載する
- 開発版で、5 秒の値を再ビルドなしで変更して試せるようにする。方法（環境変数など）は実装者が決め、`scripts/dev-install.sh` でインストールした開発版と、デモのモードの両方で使用できることを確かめて、完了報告に手順を記載する。この切り替えは DESIGN.md には記述しない

### 画面

- `Filter` の文字、山形、青い点、要約、選択肢の領域のコントロールは、macOS の標準のコントロールを使用する（DESIGN.md「画面構成」）。見た目と寸法はボードに従う
- 選択肢の領域を開閉したとき、カードの列の高さが変化する。開閉の前後で、選択と、カードの列の先頭に表示していた項目を保つ（DESIGN.md「Filter」の「開いているとき」）
- M7 のキーの監視はウインドウ単位で、文字の入力だけを除外している。選択肢の領域のコントロールがキーのフォーカスを受け取らないことを、実機と Full Keyboard Access をオンにした状態で確かめ、確認方法を完了報告に記載する
- ツールチップ（青い点、省略した要約、`Compact`）は、M7 の 0.4 秒の仕組みを使用する
- `Grouping…` は、今と同じく Group by のメニューの末尾に配置する

### M7 の開発版の `Show muted`

- M7 の開発版の `showMuted.<account>` の値は引き継がない（2026-11-15、所有者の決定。M7 は公開していないので、値を持つのは開発版を入れた環境だけである）。鍵は読み込まず、削除もしない

## 危険な箇所と確認すること

- **操作の速さ**：M7 の基準（DESIGN.md「実装方針」の「操作の速さ」）を保つ。Filter の指定の変更と、選択肢の領域の開閉も、200 枚のカードで入力から描画まで 100 ms 以下にする。計測は画面に表示しないモード（`SHIIBAR_GH_PERF_HIDDEN=1`）で行い、変更と関係のない計測は実行しない（所有者の指示）
- **一覧の描画の一致**：一覧の描画を変更するので、`SHIIBAR_GH_PERF_CONSISTENCY` の確認（行の画像の画素単位の比較と、カードとグループの見出しの比較）を実行し、Filter の指定を変更する場面と、`Unread only` でカードが消える場面を確認の場面に加える
- **`Unread only` と選択**：選択しているカードは消えないこと、↓ で次のカードに移ったあと前のカードが 5 秒で消えること、そのとき選択とスクロールの位置（選択している項目の画面の中の位置）が変化しないこと
- **隠したカードと位置**：M7 の規則（1 枚目の上半分だけが先頭の隠したカードより上になる非対称を含む）が、Filter が隠しているカードにもそのまま適用されること。`Unread only` で表示を続けているカードは、表示しているカード（位置の基準）であること
- **タブごとの指定**：All で変更した指定が Review と Mine に影響しないこと。青い点が表示中のタブだけで判定されること
- **テストの隔離**：テストは実際の Keychain、ネットワーク、状態ディレクトリ、ホーム、通知センター、ログイン項目、標準の UserDefaults に触れない

## 段階 1 の結果

段階 1（指示書レビュー）は 2026-11-15 に行った。指摘は 17 件で、実装の前に決定が必要なものは 1 件だった。結果は DESIGN.md、ボード、この指示書に反映済みである。

- `Unread only` と選択の矛盾：「選択している間は消えない」は、`Unread only` がオンの間に既読になったカードだけに適用する。`Unread only` をオンにした時点、タブの切り替え、絞る指定の変更、Dismissed の一覧、ポップオーバーを閉じたときは、選択しているカードも隠す
- ドラッグ中と右クリックのメニューを表示している間は隠さない。表示を続ける対象は「Filter が隠していなかったカード」のすべてである
- 選択肢の領域のコントロールはキーのフォーカスを受け取らない。カードの列は 100 pt 以上を保ち、足りないときは領域の中をスクロールする。Dismissed の一覧を開いている間は領域を表示しない
- 青い点の上を押したときは `Filter` の文字と同じく開閉する
- 配置先のタグは、通知と同じく検索の文字を消して区画を展開する（M7 の `SurfaceList.reveal(pr:)` と同じ動作。レビューの指摘の 1 件は「タグでは消さない」としていたが、コードと異なっていた）
- Filter の指定の変更と領域の開閉を、操作の速さの基準（100 ms）の対象に加えた
- ボードの見本のデータを青い点の規則とタブの未読の数に合わせた

所有者の決定（2026-11-15、段階 1 のあと）：`Compact` はオンとオフではなく表示の 2 つのモード（`Detailed` と `Compact`）として見せ、2 つのアイコンを並べた切り替えにする。絵柄は候補 A。指定をまとめて既定に戻すボタンは配置しない（オーケストレーターの決定）。
