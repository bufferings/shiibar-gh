# M12: Filter のオンの表示、見出しのボタンの大きさ、Refresh の回転、Dismiss all の位置、表示の形、グローバルショートカット（0.9）

Status: 作業中

最初に CLAUDE.md、docs/DESIGN.md、docs/DEVELOPMENT.md、docs/tasks/M11.md と、docs/design/ のすべてのボードを確認すること。挙動の正は DESIGN.md、見た目の正は docs/design/ である。M1〜M11 の指示書は完了した時点の記録で、DESIGN.md と食い違う箇所は DESIGN.md が優先する。0.9 で変更した文書は docs/DESIGN.md と docs/design/ のボード（Main.html、Settings.html）である。指示書と DESIGN.md が食い違う場合は、実装を止めてオーケストレーターに報告する。

## ゴール

0.8.0 のアプリの見た目と、ポップオーバーと常時表示ウインドウの使い分けに対応する。Filter の状態のボタンと切り替えのオンを、✓ と太字ではなく、薄い青の地とアクセントカラーの文字（状態のボタンは青い枠線も）で示す。見出しの 2 段目のボタンとアイコンを文字の大きさに連動させる。Refresh の実行中は、別の進行中の表示に替えず、Refresh のアイコン自体を回転させる。`Done` の見出しの `Dismiss all` を PR の数の左に移す。アカウントごとに表示の形（ポップオーバーまたはウインドウ）を記憶し、ウインドウの形では、メニューバーのアイコンを押すと、ウインドウを開く、前面に表示する、閉じるのどれかを行う。ウインドウの見出しに `Open in popover` を加える。ピンがオンのウインドウがある間は、設定画面と About も手前に表示する。アカウントごとのグローバルショートカットを加える。ウインドウを最小の大きさより小さくできる不具合が 0.8 にあるかを確かめ、あれば修正する。

アプリだけを変更する。デーモン、CLI、ワイヤ形式、DB（版 10 のまま）、Keychain の項目は変更しない。

## 実装の要点

### 実装の前に確認すること

外部の動作に依存する点である。DESIGN.md と異なる結果になった場合は、実装を止めてオーケストレーターに報告する。

次の点は、指示書の作成で確認済みである（2026-11-21）。実装の前に改めて確認する必要はない。

- `RegisterEventHotKey(inHotKeyCode, inHotKeyModifiers, inHotKeyID, inTarget, inOptions, outRef)`：1 つのアプリの中で同じ組み合わせを 2 つ登録できない。ホットキーは通常は排他でなく、押されるとその組み合わせのすべての登録者に知らせの出来事を送る。`kEventHotKeyExclusive` の登録者がいる間は、排他でない登録者には知らせない（排他でない登録は受け付けられる）。押されたときは `kEventHotKeyPressed` の出来事の direct object に `inHotKeyID` が入る。`eventHotKeyExistsErr` は -9878（macOS 27.2 の SDK の `CarbonEvents.h` と `CarbonEventsCore.h` を読んで確認）。アカウントごとに異なる `EventHotKeyID.id` を割り当て、押されたときの id でアカウントを決める
- `NSWindowCollectionBehaviorMoveToActiveSpace`："When the window becomes active, move it to the active space instead of switching spaces."、`NSWindow.isOnActiveSpace`：表示しているウインドウでは今の Space に表示しているかを示す、`NSWorkspace.accessibilityDisplayShouldReduceMotion`：「視差効果を減らす」の値（変化は `accessibilityDisplayOptionsDidChangeNotification` を `NSWorkspace.shared.notificationCenter` で受け取る）、`NSWindow.attachedSheet`：シートがなければ nil、`NSEvent.addGlobalMonitorForEvents`：キーの出来事にはアクセシビリティの権限が必要で、出来事の配送を止められない（developer.apple.com のドキュメントの JSON を読んで確認）
- SDK の `NSWindow.h`：レベルが通常でないウインドウの既定の collection behavior は Transient（"Floats in spaces, hidden by exposé"）

段階 1〜4 の結果は、DESIGN.md、ボード、この指示書に反映済みである（2026-11-21）。

- 段階 1（指示書レビュー）の指摘：通常のアプリの保持の移し替え、アクティブ化の未確認、ショートカットの登録の対象と重複の判定、記録の終わりの登録の戻し方、シートを表示したポップオーバーの閉じ方、メニューとモーダルのダイアログの間の動作、2 段目の幅が足りないときの順、Filter の押している間の表示、ウインドウの最小の大きさの引き上げ、CLI の例外（DESIGN.md「CLI（AI 連携）」と CLAUDE.md）を反映した
- 同じ組み合わせを 1 つのアプリで 2 回登録すると、2 回目は `eventHotKeyExistsErr`（-9878）を返した（このアプリのコードを含まない最小のアプリ、2026-11-21）
- 設定画面の削除の確認（SwiftUI の alert）は、設定画面に付くシートで、`attachedSheet` があり `NSApp.modalWindow` は nil である（最小のアプリ、2026-11-21）
- ウインドウの最小の大きさ：画面に表示しない位置に置いた同じ形のウインドウ（文字の大きさ 9、12、18）で、表示したあとも `contentMinSize` が保たれ、shiibar-cc で起きた事象は再現しなかった（2026-11-21）。ドラッグでの確認は段階 6 で行う
- 最小の高さ（計測のモード、2026-11-21）：ポップオーバー 300、359、497 pt、ウインドウ 300、327、465 pt（文字の大きさ 9、12、18。ウインドウは選択肢の箱が折り返さない幅）。幅 460 pt のウインドウで文字の大きさ 18 のときは、箱が折り返して 549 pt（0.8 は 537 pt）。DESIGN.md「最小の高さ」を、最小の高さが文字の大きさと今の幅で決まる形に書き直した
- 下の確認できていない点（アクセシビリティの権限、前面のアプリへのキーの配送、アクティブ化など）は、キーやマウスを操作する人が必要なので最小のアプリでは確認できず、段階 6 で確認する

次の点は確認できていない（DESIGN.md「未決」）。実装の前に、このアプリのコードを含まない最小のアプリで確認し、方法と日付を完了報告に記載する。

- グローバルショートカットに登録した組み合わせが、前面のアプリに届かなくなるか
- `Keep on top` がオン（`.floating`）のウインドウに `.moveToActiveSpace` を加えたとき、ほかの Space に移ってから `isOnActiveSpace` が偽になり、前面に表示すると今の Space に移るか（Transient の既定の動作との組み合わせ）。DESIGN.md の表のとおりにならない場合は報告する
- アイコンまたはショートカットで前面のウインドウを閉じ、アプリが常駐の状態に戻ったとき、キーの入力が直前に前面だったアプリに戻るか
- `Open in popover` で、ウインドウを閉じた直後にポップオーバーを開いたとき、アプリが通常のアプリのままでポップオーバーがすぐに閉じないか
- ほかのアプリが前面にあるときに、アイコンとグローバルショートカットでウインドウを開くか前面に表示したとき、アプリがアクティブになってウインドウがキーウインドウになるか。ポップオーバーを開いたとき、すぐに閉じずに表示を続けるか（SDK の `NSApplication.h` は `activate` でアクティブになることを保証しない）
- グローバルショートカットでポップオーバーを閉じたとき、キーの入力が直前に前面だったアプリに戻るか（上のウインドウの項目と同じ確認）
- `RegisterEventHotKey` が、アクセシビリティの権限を与えていないアプリで登録でき、押したときに知らせが届くか（権限のダイアログが出ないこと）
- Dock のアイコンと ⌘Tab で複数のウインドウを前面に並べたとき、どのウインドウがキーウインドウになるか（アプリは指定しない。結果を記録するだけでよい）
- メニューバーのアイコンが見えないとき（ノッチ、メニューバーを自動で隠す設定、別のディスプレイ）のポップオーバーの位置と、今の Space がほかのアプリのフルスクリーンの Space のときのウインドウ（ピンのオンとオフ）とポップオーバーの表示の位置。どちらも特別な処理はしない（DESIGN.md「表示の形」）。結果を記録するだけでよい

### グローバルショートカット

- ShiibarGhCore（Foundation だけ）：組み合わせの型、検証（⌃、⌥、⌘ のどれかを含む、または F1〜F20）、表示の文字（⌃⌥⇧⌘ の順と、キーの名前）、キーの名前の決め方（`Space`、`F1`〜`F20`、メニューの記号、それ以外は記録した時点の配列の文字を大文字で）、保存の形式（JSON の文字列）と読み込み（読めない値、検証に合わない値は未登録）、記録の状態の機械（記録開始、キー、中止、×、登録の結果）を置く。shiibar-cc のリポジトリの `GlobalShortcut.swift` と `GlobalShortcutRecorder.swift`（`ShiibarCcCore`）を参考にしてよいが、gh はアカウントごとに 1 つで、記録中はすべてのアカウントの登録を解除し、ほかのアカウントと同じ組み合わせを登録の前に拒否する点が異なる。重複の判定は、キーコードと修飾キーで行い（キーの名前は比べない）、相手はアカウントの一覧にあるほかのアカウントの保存している値（登録できているかどうかに関係しない）である。登録の順で結果が変わらないようにするためである。アプリ自身のショートカット（⌘R など）とシステムのショートカットと同じ組み合わせは拒否しない
- 保存：`UIStateStore` にアカウントごとの鍵（例：`v4.shortcut.<account>`）。`account_removed` で登録を解除して削除する
- 登録（ShiibarGhApp）：Carbon の `RegisterEventHotKey` を、アプリの出来事の対象（`GetApplicationEventTarget()`）に、アカウントごとの `EventHotKeyID`（署名は gh の固定の値、id はアカウントごとの番号）で登録する。押されたときの処理は 1 回だけ組み込み、id からアカウントを決めて、アイコンを押したときと同じく判定して実行する（メインスレッド）。登録の処理はプロトコルにし、テストは実際の登録をしない代わりのもの（spy）を使用する
- 登録の対象：アカウントの一覧（デーモンから受け取った一覧）にあるアカウントの保存している値だけを登録する。一覧からなくなったアカウント（DB を読めないときを含む）は登録を解除し、値は残す。値の削除は `account_removed` だけである。一覧に戻れば登録する。起動時は、一覧を受け取った時点で登録する。失敗したアカウントは、値を残したまま未登録で、欄に `Record Shortcut` を表示する
- 記録中：記録を始めたら、すべてのアカウントの登録を解除する。記録を終えたら、ほかのアカウントの登録を元に戻し、記録したアカウントは、成功なら新しい組み合わせを、中止と拒否なら以前の組み合わせを登録し直す。元に戻せなかったアカウントは未登録として表示する
- システムの拒否：SDK の `CarbonEvents.h` の説明の範囲では、排他を指定しない登録が拒否されるのは同じアプリの中の重複などである。ほかのアプリが排他で登録している組み合わせは、受け付けられても知らせが届かず、アプリは検出できない（DESIGN.md「グローバルショートカット」）。そのため拒否の文言は、`RegisterEventHotKey` がエラーを返した場合だけに表示する
- 計測のモード（`SHIIBAR_GH_PERF=1`）では登録しない。デモのモード（`SHIIBAR_GH_DEMO=1`）は登録する（デモは記憶をメモリーだけに持つので、終了すると消える）
- 設定画面：`AccountsTab.swift` のアカウントの Account の見出しの `Menu bar icon color` の次に `Global shortcut` の行を加える。欄は Settings.html の `.gsk` の見た目と DESIGN.md「定数」の「Global shortcut の欄」（高さ 22 pt、最小の幅 120 pt、角の半径 6 pt、記録中はアクセントカラーの 2 pt の枠線）。押下は欄の全体で受け取り、記録中はキーの出来事を、設定画面のほかのショートカットより先に受け取る（shiibar-cc のリポジトリの `GlobalShortcutField.swift`（`ShiibarCcApp`）の、ローカルのイベントモニターで受け取る方法）。欄の外の押下、設定画面がキーウインドウでなくなったとき、閉じたとき、選択しているアカウントが変わったときは中止する。説明の下の文言は、Text size の範囲外の文言と同じ表示にする
- アクセシビリティ：欄の名前は `Global shortcut`、値は欄の文字。× の名前とツールチップは `Clear shortcut`

- テストと確認で、実際のグローバルショートカットを登録しない。最小のアプリでの確認で登録する場合は、確認のあとに解除し、利用者が使用していない組み合わせ（F18 などのファンクションキー）を使用する
- 画面に表示される計測を繰り返さない。確認は画面に表示しないモードで行う
- コミットはオーケストレーターの指示があるまで行わない
- 完了報告には、実装者が決めた点と、仕様の矛盾や不足を記載する。ビルドの警告の件数も記載する
